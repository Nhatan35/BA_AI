## Records and transaction boundaries

Source has mutable name/type/description/owner/date/trust/status/revision. SourceVersion has immutable filename/MIME/size/SHA-256/key/version number/creator/time. Separate ParseRun has parser identity/version, status/error, extraction metadata and attempt number. ParsedSection has ordered text, NFC search text, locator/reference and cells. Evidence pins a successful parse, source/version and immutable locator/quote; summary/type/classification/confidence are editable with revision checks. Every row has project_id and composite lineage FKs. SRC/EVD codes and version/attempt numbers allocate under a project advisory transaction lock.

Upload: authorize editor and validate → exclusively write generated raw object → commit Source/Version/PENDING attempt/audit → commit PROCESSING/audit → bounded parser subprocess → recheck live editor membership → append sections/final result/audit atomically. Ordinary registration failure rolls back and removes only its uncommitted file. Parsing failure keeps the raw original. Terminal attempts and sections are immutable; reparse appends a new attempt without moving evidence.

Small-file parsing is synchronous to the caller; thread-pool execution keeps the event loop available. DocumentParser/isolated_parse form the later job boundary. No distributed worker/broker/job table/automatic retry exists. A crash can leave PENDING/PROCESSING or an orphan raw file. Explicit reparse recovers by appending an attempt. Operator `scripts/inspect_storage.py` reports counts of missing/unreferenced objects and unfinished attempts without deleting anything. Retention/reconciliation policy remains deployment work.

## Private storage and validation

Storage protocol: put/read/discard_uncommitted. LocalStorage root defaults to workspace var/storage, outside public frontend files. Tests isolate var/test-storage and var/e2e-storage. S3-compatible adapter is future work. Keys are exactly `{project_uuid}/{source_uuid}/{version_uuid}.bin`, generated by the server and checked against authorized project and DB identity constraints. Resolved paths must remain inside the configured root, including existing symlink resolution. Exclusive creation prevents overwrites. Filename is display metadata only; paths, colon, controls, empty/overlong names are rejected.

No public mount/URL/key/path appears in responses. Downloads authorize scoped records, verify original size/SHA-256, audit, and return octet-stream attachments with nosniff/sandbox headers. React renders extracted Markdown/formulas/instructions as text. OS ACLs/backups are operator responsibilities; checksum detection is not an OS append-only guarantee. Same-project SHA-256 matches show up to20 duplicate version IDs without deduplication/rejection or cross-project inference.

Extension and declared MIME must agree. application/octet-stream is accepted as a generic browser declaration only after content checks. Text/CSV require strict UTF-8/BOM and reject binary controls; PDF needs `%PDF-`; DOCX/XLSX need ZIP signature plus matching package validation. Unsupported extensions/signatures/MIME/encoding fail before commit. Corrupt signed files remain registered FAILED; encrypted/macro/entity/type-mismatched packages have explicit safe errors. No raw exception, stderr, filename path or document text enters errors/audit.

## Six parsers

| Input | Extraction/reference | Fidelity limit |
|---|---|---|
| TXT/MD | UTF-8 Unicode logical lines, blanks retained; Lines 1–3 | Markdown stays plain text |
| Text PDF | pypdf6.19.0 ordered page text; Pages 1–2 | No OCR/layout reconstruction; encrypted unsupported; no text → UNSUPPORTED_OR_OCR_REQUIRED; mixed image pages may be empty |
| DOCX | python-docx1.2.0 body paragraphs/headings/tables in document order, row/cell references | No physical page numbers or header/footer/comment/text-box/nested-table fidelity guarantee; heading label≤200 chars |
| CSV | Python csv strict comma-delimited UTF-8, row1 headers, logical rows and column-letter cells | Multiline quoted cells count as one row; no delimiter autodetection |
| XLSX | openpyxl3.1.5 read-only, sheet order/names and original row/cell refs; Booking!A12:D12 | Formulas remain expressions, never evaluated; links not fetched; blank rows skipped without renumbering |

ZIP entry/expanded-size/XML entity/DTD/macro and worksheet-dimension guards apply; defusedxml is installed for openpyxl. Subprocess timeout/capacity is **not an OS sandbox or hard memory quota**. Production needs resource limits and malware/sandbox review. Compressed PDF streams can expand before size validation completes, so peak-memory guarantees are not claimed. [pypdf extraction](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md), [python-docx API](https://python-docx.readthedocs.io/en/latest/api/document.html), [openpyxl reader](https://openpyxl.readthedocs.io/en/stable/api/openpyxl.reader.excel.html).

## Evidence, permissions and lifecycle

Locator kinds: LINE/PDF_PAGE/DOCX_PARAGRAPH/DOCX_TABLE/CSV/XLSX, inclusive start/end, plus sheet/table/columns where applicable. Service validates the available range, derives reference/heading and requires submitted quote to occur literally in selected extracted text. Omitted quote uses the selected range. Empty/out-of-range/oversized refs fail. This verifies citation placement, not semantic entailment of a summary.

Classes: FACT, ASSUMPTION, QUESTION, DECISION, RECOMMENDATION, RISK, ACTION_ITEM. FACT labels a cited statement, without approving requirements/clinical policy. Confidence is optional0–1 with no automated threshold. Corrected provenance requires new Evidence. Metadata PATCH uses expected_revision, audit and clears confirmation. BUSINESS_OWNER/PROJECT_ADMIN can confirm/withdraw evidence, with server-derived actor/time and revision check; this explicit MVP assumption grants no business/clinical approval.

All seven active project roles read sources/versions/parsed/evidence/search/originals. BA/PROJECT_ADMIN upload/reparse/edit source/evidence metadata. BUSINESS_OWNER additionally confirms evidence. Audit remains PROJECT_ADMIN-only. System admin has no project bypass. Source ACLs/sharing are absent. Membership revocation applies to each request and is rechecked after parsing.

Source status is human-controlled ACTIVE/SUPERSEDED/ARCHIVED. Archival retains history and blocks version upload until explicit activation. Optional same-project supersedes_source_id atomically marks the older active source SUPERSEDED. Self-links, existing-link removal, cycles and replacement chains are conservatively rejected. Direct explicit status marking without replacement link is allowed. No newest-date automatic winner exists.

## Project search

PostgreSQL simple-config full-text matching uses a GIN expression index, parameters, project filters and RLS. All versions of ACTIVE sources are searched using each version's latest **successful** parse. Failed retries preserve prior searchable extraction; old parse sections remain accessible to citations without duplicate hits. include_inactive=true explicitly includes ARCHIVED/SUPERSEDED with status. Results include project/source/version/parse IDs, source name/code, filename, excerpt around matched words and exact reference. No embeddings, AI, query logging or HTML highlights. Unicode/case-insensitive tokens are supported; stemming/fuzzy/substring/accent folding and phrases spanning sections are not. Search inclusion is not approval.

## REST contract

Paths follow `/api/v1/projects/{project_id}`. Accepted cookie/Origin/CSRF rules apply. Inaccessible records return generic404; invalid input safe422. Upload returns201 even for a registered terminal parse failure; inspect parser_status/error.

| Method/path | Behavior |
|---|---|
| POST /sources | Multipart file + metadata JSON string → source/version |
| GET /sources; GET /sources/{id} | Cursor register/detail |
| PATCH /sources/{id} | Partial metadata/status + expected_revision, optional supersedes_source_id |
| POST /sources/{id}/versions | Multipart file only → source/version |
| GET /sources/{id}/versions; GET .../versions/{version_id} | Version list/detail with derived parser result/duplicate IDs |
| GET .../versions/{version_id}/download | Authorized audited original attachment |
| GET .../versions/{version_id}/parses | Latest100 attempts |
| POST .../versions/{version_id}/reparse | Append attempt and return bounded result |
| GET .../versions/{version_id}/parsed | Optional parse_run_id/after_ordinal/limit → parse/items/next_ordinal |
| POST/GET /evidence; GET/PATCH /evidence/{id} | Manual create, list optionally source_id-filtered, detail/metadata revision |
| POST /evidence/{id}/confirmation | expected_revision/confirmed human command |
| GET /search | q/include_inactive/offset/limit → items/next_offset/policy |

Evidence create accepts source_id/source_version_id, optional parse_run_id, locator, classification, optional exact extracted_text/summary/type/confidence. Example locator: `{"kind":"LINE","start":2,"end":2}`. Unknown JSON/multipart fields and client project/actor/confirmation/storage identities are rejected. VersionRead omits storage_key and derives parser fields from ParseRun. Stable Evidence IDs support future same-project requirement/rule/question/trace links.
